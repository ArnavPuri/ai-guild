# UX Microcopy

Make every word on the screen help someone finish what they came to do.

## Ask first

If missing: what the screen or flow is for, who uses it, the product's tone (friendly, neutral, formal), and the current strings or a description of each element.

## Steps

1. List every string with where it appears (button, label, error, empty state, toast).
2. For buttons, use a verb that says what happens next: "Save changes", "Send invoice", not "OK" or "Submit".
3. For errors, say what went wrong and how to fix it, in that order, without blame: "That card has expired. Try another card."
4. For empty states, say what will appear here and give the one action that fills it.
5. For confirmations of destructive actions, name the thing and the consequence: "Delete 3 files? You cannot undo this."
6. Keep the same word for the same thing everywhere; flag any place the original used two words for one thing.
7. Keep strings short enough for a phone screen; note any that will be tight when translated.

## Output

A table with Element, Current, Proposed, Why. Then a short list of terms to keep consistent.

## Check before replying

- No jargon or internal names the user would not know.
- Every error message contains a way forward.
- Buttons still make sense if read alone by a screen reader.
